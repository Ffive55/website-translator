# v0.3.15 启动与数据完整性修复

2026-10-31。针对 v0.3.14 重新加载后长时间等待、弹窗及设置入口无响应的问题进行复核。仅更新本仓库 Edge 解压目录，保留此前未提交修改；未打包、安装本地主机、改注册表或推送。

## 启动等待的原因和修复

v0.3.14 将整个界面设为 inert，首次状态请求又等待旧数据迁移、指纹生成和 IndexedDB 写入全部完成。旧历史按每个操作复制所有祖先，指纹查找还会为每条词条重新扫描全部操作；迁移逐条读取和写回越来越大的分组对象。空配置及小词库测试漏掉了这一成本。

v0.3.15 保留完整操作历史，以精确的整数区间表达因果祖先，按依赖顺序处理乱序记录；版本查找建立一次索引。词条按主域名分组批量验证、提交，启动标记仅在成功写入后变为 active。迁移过程主动让出事件循环并提供阶段进度。

弹窗设置入口与后台迁移独立，移除整页 inert。状态请求不等待完整迁移，超时会提示并重试；状态刷新合并，首次返回不会覆盖用户已编辑的表单。词库尚未就绪时拒绝翻译和词条写入，避免先请求 AI、后因迁移失败而不能保存。原始数据库和手动队列保留，不要求卸载扩展或清空存储。

## 数据风险及处理

| 复核项目 | v0.3.14 的问题 | v0.3.15 处理 |
| --- | --- | --- |
| 备份待上传状态 | 合并时以备份增量作远端，误用 pending 结果，可能只显示文本而丢掉上传标记 | 对合并后的实际内容相对共同基线重新生成本地增量，保留双方修改及显式删除 |
| 旧备份与新词库 | 导入会直接覆盖当前基线和缓存文件 | 不同内容修订拒绝覆盖；相同修订仅合并无冲突数据，已有可信文件继续保留 |
| 跨仓库切换 | 扁平指纹被另一仓库覆盖，返回时重放已放弃的旧人工译文 | 迁移标记按仓库隔离；兼容升级旧标记，不盲目重新应用旧源值；批次固定仓库及上下文 |
| 移除网站 | resetLocal 会清空其他仓库同网址的本地层 | 限定当前仓库；移除的未上传增量保存在可导出归档中 |
| 导入中断 | IndexedDB 已提交而浏览器数据库失败会留下半完成状态 | 先持久化导入日志及导入前备份；IndexedDB 与日志 ID 同事务记账，重试幂等；重启自动继续，未完成时禁止其他词条写入 |
| 多文件导入 | 前面的文件可能已写入，后续坏文件才失败 | 先解析、校验所有选中文件，再合并为一次有日志的导入 |
| 未完成导入 | 缺少操作入口，容易误认为已完成 | 提供继续导入、导出导入前备份；仅在确认未写入时允许取消；初始化失败也能导出原始数据 |
| 上传等待中的修改 | 创建 Git 对象后未重新验证本地状态 | 更新分支前再检查本地上下文、版本和远端分支；拒绝强推，未确认发布不清除修改 |
| 缓存读写竞态 | 更新清空缓存后，较早的读取可能填回旧值 | 缓存按代次接收结果，旧读取不能重新覆盖新代次缓存 |
| 同步与恢复排队 | 自己写出的多个分片会触发重复恢复和重写 | 合并恢复请求；无变化时不重复应用设置，导入期间暂停恢复 |

原有 B/L/R 冲突选择、目标语言隔离、选区及敏感文本保护继续保留。备份导入校验范围、语言、词条身份、修订和服务目录；来源文件和 GitHub 数据均不执行其中的脚本。

## GitHub 拒绝访问与限流

旧提示将 403 和 429 合并，不能据此确定用户实际遇到的是权限问题还是限流。新版根据 HTTP 状态、剩余配额、Retry-After、重置时间及错误类型分类：权限不足提示检查当前 Token 的仓库和 Contents 权限；限流暂停至等待时间；网络失败暂缓自动请求。同一恢复轮次共用固定提交，不按每个网站重复读取总索引。明确的授权拒绝后不继续自动请求，用户主动检查或重新保存配置可重试。

这些错误只影响 GitHub 访问，不阻塞本机设置和已有词库。Token 仍只在当前设备保存，错误信息不回显凭据或服务器正文。规则依据为 [GitHub REST 错误说明](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api)。
