# v0.3.3 动态分批与有限并发

仅更新 Edge 解压目录，不打包。默认单次输入上下文上限为 **200,000 个估算 token**，包括提示词、术语表、原文、上下文/路径和消息格式开销；**不计预计输出，不预扣输出空间**。

## 分批与服务兼容

`extension/managed-batching.js` 为浏览器和本地连接程序共用的分批规则。按实际文本量组合请求，不再对对话模型和 ChatGPT 订阅固定每批 20 条。估算使用 ASCII 字符约 2:1、非 ASCII 使用 UTF-8 字节数的保守规则，不代表各模型 tokenizer 的精确计数。

输入未达到预算时不会因预计输出而拆批。实际服务拒绝上下文长度、输出截断、结果格式不完整或响应超过传输限制时，再按文本量对半拆小重试。输入消息和实际响应仍有独立的传输字节安全上限，尤其 Native Messaging 主机响应必须小于 1 MiB。这些上限不作为预计输出扣减 200K 输入预算。

普通机器翻译服务遵循其接口限制：DeepL 最多 50 文本/请求，Google 最多 128 文本且控制请求字符量，Azure 控制请求字符量，Qwen-MT 接口每次只有一条 user 待翻译消息。200K 规则不能改变这些原生协议。

## 并发、重试与结果保留

- 全局最多 2 个在途翻译请求，不同网站和采集子域名共用请求槽。批次可以乱序返回，持久化仍由后台单写者串行提交。
- 每个任务固定启动时的服务、模型和提示词。切换设置只影响后续任务；网站停用、删除或目标语言改变仍会停止新请求，并拒绝迟到结果。
- HTTP 408 / 429 / 常见 5xx、网络错误和超时退避重试，最多额外 2 次。支持服务返回的 Retry-After（当前单次等待上限 60 秒），否则采用指数退避并加小幅随机延迟。
- 上下文或输出问题递归拆分，最多 8 层、每任务累计最多 16 次拆分；单项或达到拆分深度后仍有界重试。认证或配置错误不无限重试。
- 每批全部结果通过协议校验后才保存；成功批次立即可本地复用，并自动写入已确认同步目录。其他批次失败不回滚成功结果。
- 待处理输入保存在浏览器本机的 `wt_task_inputs`，不含服务密钥、不进入 OneDrive 同步。提交多域名采集时，任务与可恢复输入一起持久化。完成的批次从待处理输入中移除。
- 自动重试耗尽或后台重启后，在“翻译记录”点击“重试剩余内容”。只提交剩余原文，已完成词条不重新请求；成功后移除对应任务草稿。状态栏显示动态批次和重试次数。

## 本地计算优化

词库合并结果按变更记录版本缓存；批量写入先计算一次依赖头，随后词条沿批内因果链追加，不再每写一条就重新合并整份数据库。页面通知合并调度，不阻塞下一批翻译请求。订阅请求共享凭据时短暂等待会话锁，避免并发读取/续期互相抢占。

## 验证范围

测试使用合成词条、模拟 API 和独立 Edge 配置，不使用真实账号或真实订阅令牌。覆盖 500 短标签单请求、输入未满 200K 不预扣输出、长文本拆分、全局两请求并发、跨网站并发、429 退避、服务上下文拒绝后拆分、失败批次手动恢复、已成功词条不重复请求、Native 订阅超过 20 条和输入预算拒绝。

Edge 网络层测试额外验证 160 个短标签只请求一次，60 条长文本经跨页采集合并后分成多批，实际最多两个请求在途。请求轮次减少不等于真实服务等比例加速；模型生成速度、思考强度、服务限流和网络仍会影响总耗时。

本轮结果：Edge 构建通过；98 项功能/协议测试和 13 项词库回归全部通过；独立 Microsoft Edge 烟测通过。实际模拟服务请求统计为：160 个短标签 1 次请求，60 条长文本 3 次请求，峰值并发 2。另一个 500 短标签后台回归也只发出 1 次请求。没有生成 v0.3.3 压缩包。

参考：[OpenAI 限流与指数退避说明](https://developers.openai.com/api/docs/guides/rate-limits)。
