# GitHub 词库协议与迁移基础

日期：2026-10-31；实现版本 v0.3.18，协议版本 1。统一模块已接入正常后台、页面和管理界面。实际验证边界见 [实施计划](GitHub词库迁移实施计划.md)。

## 数据和目录

`extension/dictionary-core.js` 将统一数据协议挂在 `WTCore.dictionary`，浏览器和 Node 共用。`dictionaries/index.json` 只引用 `dictionaries/<group>/manifest.json`，清单再引用 `<BCP-47>/<stable-id>.json`。文件只含 JSON，不接受脚本、任意 URL 或动态处理器。

主域名继续使用 tldts，开启 `allowPrivateDomains`，例如 `tenant.github.io` 按租户隔离，`example.co.uk` 不会错误归入 `co.uk`。完整 origin 必须规范化且没有用户名、密码或路径。普通 HTTPS 域名用域名作文件 ID；HTTP、端口或 IPv6 等特殊 origin 使用完整 UTF-8 字节的十六进制稳定 ID。国际化域名保留规范 punycode；完整 origin 始终保存在数据中。

索引、清单、数据包都包含 `schemaVersion` 和 `minReaderVersion`。当前只接受协议 1；更高版本直接拒绝。每种语言的 `revision` 是该语言的明确网址及文件描述列表的规范 JSON SHA-256，不包含插件版本、源码提交、README、转换报告或其他语言。单个文件另有原始 UTF-8 字节长度及 SHA-256。哈希只检查完整性，来源身份由本机受信任仓库配置和 HTTPS 确定。

检查与下载先解析分支的完整 40 位提交，再从该提交读取全部数据。不会从索引接受其他仓库或下载地址。分组检查对已安装网址及其共享依赖另外计算选择修订；其他未安装网址的更新不会形成当前组的无关升级。只读客户端限制 GET、禁止重定向、限制响应字节及 30 秒请求时间。同一客户端的索引检查合并在途请求并缓存 60 秒，清单缓存至多 100 份；分组与文件顺序请求以限制峰值内存。401/403/404/429 分别保留授权、未发布与限流失败信息。

## 数据包

顶层固定字段如下；未知字段、重复身份和扩大网址范围直接拒绝：

```json
{
  "schemaVersion": 1,
  "minReaderVersion": 1,
  "group": "example.com",
  "targetLanguage": "zh-Hans",
  "origins": ["https://example.com"],
  "kind": "entries",
  "records": [],
  "adapter": null
}
```

`kind=entries` 用于新增和人工词条。每个 record 包含 `site` 与 `entry`，删除时额外含 `deleted:true`。entry 通过现有 `WTCore.validEntry` 校验，身份为完整网址、路径、上下文、源文及目标语言；保留 `origin`、`action=skip`、`userSelected:true` 等含义。内部合并表用显式 `null` 表示已删除；缺项表示没有新的声明，不能推断为删除。删除个人网站记录独立于词条删除，不修改公共词库。

`kind=site` 和 `kind=github` 用于保留旧适配器的完整结构，当前仅允许 `zh-Hans`。adapter 为有界、无环的对象图，保存对象别名、数组顺序、页面分类、选择器、属性、忽略范围及规则顺序。内部 `zh-CN` 只是旧 GitHub 引擎的兼容字段，不是第二套目标语言。

正则对象包含 ID、source、flags，必须与本地 `dictionary-policy.json` 完全一致。函数只能引用本地 `github-dictionary-handlers.js` 中的固定 ID；hydrate 不使用 eval、Function、远程 import 或脚本注入。处理器闭包绑定当前词库，保持日期和相对时间效果。当前 53 个函数的本地代码保留上游 GPL 及版权头。

受审范围模板保存在本地白名单：允许静态映射添加或修改译文、现有正则/选择器规则修改文本替换值；页面匹配、选择器、属性、忽略规则、正则执行顺序和函数 ID 必须保持模板一致。新增页面、正则、执行范围或函数须先审阅本地代码并更新兼容白名单。不能靠远端数据扩大页面保护范围。导入 `userSelected` 不能改变现有内容引擎的输入和敏感数据保护。

## 容量与存储

| 项目 | 当前限制 |
| --- | ---: |
| 总索引、单份分组清单 | 各 512 KiB |
| 单词库文件 | 12 MiB |
| 一个分组/语言候选包 | 32 MiB、最多 400 文件 |
| 单包/分组增量记录 | 最多 50,000 条 |
| 对象图 | 50,000 节点、200,000 边、40 层 |
| 单组明确网址 | 最多 200 个 |
| 旧数据库纯转换 | 32 MiB |

新缓存选用 IndexedDB，避免将大 GitHub 包、基线和候选同时塞入有默认容量限制的扩展 local 存储。`dictionary-store.js` 只保留每个仓库/分组/语言的一份基线、一份本地修改层和一份待解决候选；不保存无限远端历史。旧数据回退备份独立保留。容量超限或存储事务失败不截断数据，也不替换旧词库。浏览器真实磁盘配额仍由设备决定，不承诺无限容量；语言/仓库切换后的缓存清理策略尚待接入阶段实现。

候选包先在事务外完成所有文件校验和修订核对，再在 IndexedDB 写事务内重新核对上下文代次并读取最新本地修改，完成比较与整组提交。下载、校验或任一文件失败都不切换。出现冲突时保留旧基线和本机效果，候选放入暂存；全部解决后一次切换。冲突处理期间发生本地编辑会使旧解决操作失效，要求重新合并。网址删除、语言或仓库改变会使旧上下文结果失效。设置、启用状态和主机权限始终在缓存外，安装词库不会授予权限或改变启停状态。

## 比较与本机旧数据

三方比较当前覆盖增量词条，以 B 基线、L 本地、R 远端的完整规范记录为单位，不读取电脑时间：独立变化合并，相同完整结果去重，同键不同结果及删除/修改形成可见冲突。输出原基线、本地、远端、待上传层及 `canInstall`。冲突可以选本地、远端或编辑后使用；编辑不得改变身份、语言或添加未知字段。人工及选区标记属于词条数据，不因译文字面相同而静默去掉。旧适配器保留结构。对可唯一确定的静态源文关联基线，远端变化进入三方比较；有歧义的页面规则不自动改写，人工译文以受上下文限制的增量记录上传。规则执行范围仍由本地白名单约束。

v0.3.18 按用户要求删除旧文件格式校验、迁移转换、备份导入及恢复入口。本机当前操作数据库、下载基线和本地修改层继续作为当前数据存储；不扫描或导入旧目录。

后台启动时校验并暂存旧数据库的完整历史，保留旧数据库作为本地编辑记录和迁移备份，暂停旧 OneDrive。已下载基线和本地修改在 IndexedDB 合并后供页面读取。管理页可导出备份和一次性导入校验后的旧变更文件；启动迁移失败时本机旧条目保留。

## 浏览器同步协议

同步数据只允许逐字段记录：网址的 `installed`、`enabled`、`excludedPaths`、`name`；设置的目标语言、超时、输入预算、自动展开、四项采集上限、总开关和有大小限制的提示词。AI 服务、模型、地址、区域和思考强度按白名单同步，不复制整个 AI 对象；API Key 仅通过受校验的服务设置字段同步。v0.3.19 按用户要求新增 dictionaryRepository、dictionaryToken:github/gitee，并允许 aiSettings/aiProfile 中的 API Key 随浏览器设置同步。订阅登录令牌、任务、队列、日志、基线、词条内容、设备凭据和本机权限不进入同步白名单。记录内的随机设备 UUID 仅用于逻辑计数并列判定，不是凭据。

每个字段以 Lamport 计数、设备 ID 确定顺序，不用电脑时间；相同身份却不同内容视为损坏。同计数的安装删除优先，离线更改 enabled 不会重新安装；显式重加需更高的已观察计数。删除记录不静默清理，达到容量时拒绝新增，后续须设计确认后的压缩。

`wt_install_head` 和 `wt_install_N` 分片包含同一内容修订，收齐并校验后才接受；未到达的 head 返回 null，不表示清空网站。协议单项保留在 7,000 字节以内，整个候选清单在 90,000 字节以内，最多 1,000 条字段记录，为浏览器 8 KiB/项、100 KiB 总配额留下空间。提示词同步最多 5,000 UTF-8 字节，超限应在接入界面提供留在本机的选择，不会截断。后台已接入节流、变化监听、分片校验、写前复核和恢复闹钟；全新空设备在没有用户编辑且清单未到达时不写默认清单。达到浏览器实际总容量或写频限制时保留本机数据并报告错误重试。

## 切换前置条件

2026-10-31 通过 GitHub 连接只读核实：`Ffive55/website-translator` 是私有仓库，默认分支 `main`。聊天连接不作为扩展运行凭据。私有读取和上传凭据在管理页按设备配置；已有网址缺少词库时尝试恢复，失败不调用 AI。

当前 Edge 保留本地引擎并从下载缓存加载词库；未下载时显示原文。初始 dictionaries 已于 2026-10-31 发布，提交 5c4b8f57d6f655692e8b95e9fc6f001211469bb0；连接凭据和真实双设备同步仍分别验证。构建不擅自改变现有扩展 ID；旧固定身份迁移及备份导入入口已退出。云端双设备实测和首次实际远端发布单独验收。

设计复核依据：[Chrome 扩展存储及配额](https://developer.chrome.com/docs/extensions/reference/api/storage)、[远程代码与数据边界](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)、[稳定扩展身份](https://developer.chrome.com/docs/extensions/reference/manifest/key)、[GitHub refs](https://docs.github.com/en/rest/git/refs)、[GitHub trees](https://docs.github.com/en/rest/git/trees)。这些依据说明 API 约束，不代表跨设备验收已完成。

凭据按本机服务及地址隔离保存，不随同步和备份导出；云端地址变化不会把旧地址的 Key 自动用于新地址。超过同步配额的长提示词保持本机值，不被旧云端短提示词覆盖。备份包含安装/非敏感服务设置、词库层及本机历史，导入前通过协议校验。

## v0.3.17 网站管理交互

搜索仅读取当前目标语言的总索引和经哈希验证的分组清单，按主域名或完整 origin 检索；空条件列出全部未下载网址，停用但已下载的网址不会重复列出。用户点击下载后才添加该网址并下载词库正文；同组其他未添加网址不会自动安装。仓库或语言变化使旧搜索结果失效。

主域名分组有本地新增、修改或显式删除时显示上传，顶部显示上传全部。界面不要求预览；后台仍为每组生成受验证的上传数据，复核本地修订、安装上下文与远端提交，再以非强制 Git 更新发布。远端同键冲突自动下载并暂存候选，未写远端；已有本机候选仍须显式处理。批量逐组执行，单组冲突不阻止其他组，限流、网络或授权失败停止后续请求；结果明确报告成功和失败，本地待上传内容保留。

检查更新的成功结果通过悬浮提示显示，不在列表中持久显示旧检查次数；初始化、网络失败和限流状态继续可见。GitHub 仓库页仅保存仓库、凭据和连接状态，备份及导入入口在常规设置。

弹窗检测按完整 origin 与目标语言匹配，只读索引及分组清单；未下载提供下载，有远端内容修订提供更新，本网址的本地修改层非空提供上传。这里的本地较新指存在未上传变更，不比较设备时钟；双方同时变化仍须三方合并。检测复用一分钟仓库缓存，不在 1.5 秒任务进度轮询中重复请求；失败保留本机上传入口，限流等待继续共用。网页切换或语言/本地基线变化使旧检测失效，迟到结果不展示到其他网页。

当前网页启停修改该完整 origin 的 enabled 字段，保留其他网站和翻译总开关；尚未添加的网址首次停用会记录到安装清单，便于浏览器同步其停用状态。启用/停用不调用 AI，下载、更新和上传同样不调用 AI。

## v0.3.18 当前功能范围

旧文件校验器、迁移准备/暂存、备份导出导入、导入日志恢复及对应界面和公共接口均已删除，不自动处理遗留导入日志；已有本机数据库和下载缓存继续使用，不执行删除或重新建库。GitHub 包完整性与内容白名单仍按当前协议验证，正常三方合并、冲突暂存、上传提交保护和浏览器清单恢复继续生效。

弹窗使用当前完整 origin 的轻量摘要接口，不携带词条正文、其他网站任务或 AI 凭据；本机变更通知合并刷新，十秒后备检查。管理页共用一次读取准备，只有仓库、语言或安装清单变化才更新 IndexedDB 上下文。当前操作记录不可变，保存按设备、序号和操作数判断变化并保留提交失败回滚。

搜索目录按主域名合并，子域名关键词命中整组。合并下载固定提交，一次验证所有适用包及其依赖，共享包仅下载一次；验证通过后单次加入全部已发布网址，再使用持久化下载票据和整组事务安装。原有网址的启停及本地层不改写；并发范围、语言或仓库变化会使操作失效，不覆盖新状态。搜索结果在整组下载完成后移除。
