## v0.3.16 匿名访问和限流反馈修复

用户界面确认本设备未配置凭据，当前请求为匿名访问。空 Token 保存只保存仓库地址，不能视为已经配置凭据或连接成功。v0.3.16 修改保存提示并提供令牌创建入口；已保存 Token 只代表本机存储，不代表服务器已验证其权限。

错误和状态记录匿名/携带 Token 的访问方式、响应配额和剩余量。限流等待由所有 GitHub 操作共同遵守，服务线程重启后继续生效；重复保存相同访问身份不清除等待。只有实际更改凭据才切换访问身份，真实账号的配额仍由服务器决定。诊断不存令牌内容，访问标识仅是本机不可逆摘要，不进入同步词库。

验证：限流专项独立 Edge 8 项通过，覆盖匿名提示、重复检查、线程重启、重复保存、切换访问身份及诊断脱敏；定向单元/界面 8 项通过。本轮不使用真实 Token，不打包或推送。npm test 完整回归 169 项及上游回归通过，源码白名单和差异检查通过；仅更新 Edge 解压目录。

参考：[GitHub API 限额](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[个人访问令牌](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

## v0.3.15 启动与数据完整性复核

本轮针对用户重新加载后长时间等待、设置入口无响应的反馈，复现并修复大旧库初始化路径。此前 v0.3.14 的空配置/小词库测试未覆盖这一场景。修复说明见 [启动与数据完整性修复](v0.3.15启动与数据完整性修复.md)。保留所有既有改动；本轮开始前的代码、测试、文档及元数据副本位于忽略目录 .cache/v0314-review-start/。

- 取消整页 inert，设置入口不等待完整迁移；状态请求有超时和合并刷新，进度与操作就绪分开。
- 因果历史采用精确区间和依赖排序，版本查找索引化，按主域名批量写入；旧数据库、人工候选、语言和原文来源保护保留。
- 备份合并重新计算待上传差异，不丢掉备份独有词条的待上传标记；不同远端修订拒绝覆盖，当前新版保持不变。
- 指纹及代次按仓库隔离；网站移除只影响对应仓库，未上传记录归档并包含在备份中；旧指纹兼容升级，避免重放已放弃的人工值。
- 导入采用持久化日志和导入前备份，IndexedDB 与导入 ID 同事务记账。发生跨存储失败时保留日志，禁止其他词条写入，重新加载自动继续；没有写入时可取消。
- 发布分支前再次检查本地上下文、修订和远端分支，不强推；较早的缓存读取不会填回新代次缓存。
- GitHub 权限、限流及网络错误独立处理。限流按响应头等待，明确授权拒绝不反复自动请求；一轮恢复共用固定提交，网络失败不拖住本机设置。

分组不能扩大适用范围。词条身份至少包含网址、路径或适用范围、上下文、源文及目标语言。只有明确可共用的界面词条进入共享文件。公共共享数据仍需限定适用网址；不能将同主域名下的个人或业务内容自动共享。

| 凭据与设备状态 | API Key、GitHub 凭据、订阅令牌、权限 | 本机独立保存 |
| 任务与临时数据 | 手动队列、翻译输入、日志、下载进度 | 仅本机 |

同步字段必须使用白名单，不能直接同步整个 AI 配置对象。同步写入应合并并控制频率，按实际配额设计清单分片。自定义长提示词等设置须检查大小，不承诺无限同步。浏览器同步不能替代备份，也不承诺跨浏览器品牌互通。

本地词库可使用 IndexedDB 或经容量评估后的扩展存储。需要考虑基线、暂存包和本地修改同时存在的空间，避免复制整份历史造成无界增长。优先统一数据访问层，不为了展示目录而引入磁盘文件访问。

所有导入包经过 `WTCore` 或其统一协议扩展校验：字段、体积、数量、语言、网址、路径、规则范围和内容均受限制；不接受远程脚本、任意处理器或 HTML 执行。哈希用于内容完整性，不等于来源身份；下载源固定在配置的受信任仓库，不能按远端数据任意跳转。

完成标准：协议、字段白名单、版本判定、删除和兼容规则明确，具备合法与非法包、多语言隔离等验证样例。

## 阶段二 旧词库与现有本机数据迁移

### 仓库词库迁移

| 旧来源 | 迁移方式 | 必须保留 |
| --- | --- | --- |
| Docker、Tailscale 等 `site.json` | 拆分数据和执行逻辑，生成统一数据包 | 网址和页面范围、属性翻译、规则顺序 |
| GitHub `locals.js` | 分离静态映射、规则与执行函数 | 页面分类、正则优先级、选择器范围、日期时间效果 |
| 上游同步基线与来源记录 | 继续使用受控同步流程，增加数据转换阶段 | 来源提交、版权、许可证、上游与本地冲突审阅 |

GitHub 专项步骤：

1. 清点所有词库类型，生成转换报告，包括词条数量、规则类型、来源范围、无法转换项。
2. 静态映射转换为 JSON；正则保存为受校验的数据，保留顺序与替换语义，限制复杂度和执行风险。
3. 日期、相对时间等函数留在扩展内，词库仅使用固定白名单处理器及受验证参数。不得把远程 `locals.js` 下载后执行。
4. GitHub 专用引擎从本地统一词库加载；缺少词库时显示原文，不再因 `I18N` 或 `locals.js` 缺失报错退出。
5. 将 `githubstatus.com` 按实际域名单独组织数据，同时保留它所需的本地专用适配。
6. 无法自动转换的内容逐项处理，不静默丢弃；不得把全部词库扁平化成源文到译文的简单映射。
7. 保留现有上游更新和冲突处理规则，增加统一数据包生成与校验；不直接改写上游纯基线。

保留 `text-provenance.js` 的真实原文追踪、网站自身改写失效规则、`managed-selected` 优先级及输入和敏感数据保护。导入的 `userSelected` 不能绕过这些保护。

### 浏览器数据迁移

从 `wt_database` 提取有效词条及其历史含义，转换到本地修改层；保留人工译文、手动指定标记、所有语言、跳过记录和未解决冲突。网站信息转换为个人安装清单，保留启用状态、排除路径和删除状态。

迁移顺序：读取旧数据 → 建立本机备份及迁移状态 → 转换至暂存区 → 完整校验 → 一次切换 → 保留旧数据供回退。

- 迁移要幂等，重启或重复运行不能重复导入、复活已删除网站或清空已有修改。
- 只有可以确认与远端基线一致的旧词条才视为已同步；缺少可靠基线的旧词条保留为本地修改。与远端同键但内容不同时明确处理冲突。
- 迁移期间暂停旧 OneDrive 自动交换，避免两套流程写入同一状态。
- 旧同步文件夹不自动删除、移动或清理。只存在于旧目录而未导入本机的数据，应在旧入口移除前提供一次性导入途径；实际读取用户数据时遵守当次授权范围。
- 新格式无法被旧程序直接消费，必须明确回退依赖保留的旧数据；不得声称降级可以无损读取新数据。

完成标准：转换报告无未处理项，旧翻译场景回归通过，本机迁移可恢复且重复执行无副作用。首次词库远端发布与取消内置分发需协调；远端数据尚未发布时不能宣称新安装可正常下载。

## 阶段三 本地修改与远端版本合并

### 三方比较

每个词库保留 B 基线（上次成功安装或上传确认的远端版本）、L 本地（基线加本地修改）、R 远端（此次读取的最新版本）。不能只比较两份数据或以电脑时间决定覆盖。

| 变化 | 下载更新 | 上传 |
| --- | --- | --- |
| 只有本地变化 | 保留本地修改 | 纳入上传 |
| 只有远端变化 | 接收远端修改 | 保留远端内容 |
| 两边修改不同词条 | 自动合并 | 自动合并 |
| 同一词条修改结果相同 | 合并并清除重复修改状态 | 不重复上传 |
| 同一词条修改结果不同 | 保留本地效果并标记冲突 | 解决后发布该组 |
| 一边删除另一边修改 | 标记冲突 | 解决后发布该组 |

冲突界面显示原基线、本地和远端，提供“保留本地”“采用远端”“编辑后使用”。人工修改不被静默覆盖。已有未解决的并发冲突不能在迁移或导出时随意选一个值。

区分三种删除：删除个人网站安装记录不删除 GitHub 词库；明确删除词条产生删除标记；本机缺少词条不等于删除。跳过记录也不等于删除。离线设备重连后不能复活已删除安装记录或词条。

### 下载提交与上传提交

主域名分组作为一次本地安装的完整单位：下载所需文件 → 校验整个候选包 → 合并本地修改 → 无冲突后一次切换。有冲突则暂存候选版本，继续使用旧版本和本地修改；其他组可独立成功。

上传顺序：选择分组 → 读取最新远端 → 三方比较 → 展示新增、修改、删除、冲突 → 解决冲突 → 将数据和索引放入同次 Git 提交 → 确认发布成功 → 更新本地基线。

- 更新分支时禁止强制覆盖；远端已变化则重新读取并合并。
- 网络结果不明确时先核查提交是否成功，再决定重试，避免重复发布。
- 只清除本次确认上传的修改；上传过程中产生的新修改继续标记待上传。
- 下载、上传及 AI 编辑并发时，提交前再次检查本地代次，避免迟到结果覆盖较新修改。
- 网站被删除、语言切换或仓库配置改变后，旧任务不得继续错误提交。
- 不上传整个 `wt_database`，只导出校验后的词库数据；设备操作历史和个人设置不进入远端。

完成标准：不同词条自动合并，同条不同修改和修改删除冲突可见，断网及并发不丢失数据，失败继续使用旧词库。

## 阶段四 浏览器同步与新设备恢复

首阶段验收限定同一 Edge 账号的两台 Windows 设备。解压加载必须解决稳定扩展 ID；固定身份前先评估对现有设备数据及 Native Messaging 授权的影响，不能贸然改变 ID 造成旧数据不可见。

恢复顺序：

1. 确认扩展身份，读取浏览器同步设置和网址清单。检查同步状态可知范围，不把 API 写入成功声称为另一设备已收到。
2. 将远端清单与本机状态合并。初次空数据库不能被解释为删除全部网站，也不能用默认设置覆盖尚未到达的同步数据。
3. 界面先恢复网址、开关与设置；缺少词库的显示“待下载”。
4. 从 GitHub 索引确定当前语言、已安装网址和共享依赖。
5. 固定远端提交，下载缺失包并校验协议、哈希、网址范围、语言和内容。
6. 成功后写入本地，检查实际主机权限；启用且授权的网站开始翻译。
7. 未获权限的显示“待本机授权”，由用户点击授权；词库下载不能擅自授予网站权限。
8. 后台重启、浏览器关闭或断网后恢复任务。后续新收到的网址也触发缺失词库恢复。

| 情况 | 处理 |
| --- | --- |
| 远端暂无网址词库 | 保留网址和状态，显示暂无词库，不自动请求 AI |
| 当前语言无词库 | 显示暂无此语言，不混用中文或其他语言 |
| GitHub 不可访问 | 保留已有词库，显示失败和重试入口 |
| 私有仓库缺少授权 | 要求本设备配置读取授权，不同步凭据 |
| 协议不兼容 | 提示升级插件，拒绝安装不兼容包 |
| 网站原本停用 | 可下载数据，保持停用，不翻译或残留语言标记 |
| 旧设备有未上传词条 | 新设备无法恢复；旧设备保留待上传提示 |

浏览器网址清单应有稳定身份和删除信息，设置冲突采用明确的逐记录合并规则，并控制删除记录保留与容量；不能整表覆盖或无限增长。

完成标准：设置与网站状态正确恢复，下载全过程无 AI 请求，无空清单覆盖和网站复活，真实两设备流程通过。

## 阶段五 网站管理与词库上传界面

网站管理顶部常驻“检查更新”，检查发现有新版后出现“全部更新（N）”，N 按主域名分组计数。更新按钮只在分组行出现。

```text
已添加网站                     [检查更新] [全部更新（2）]

▸ docker.com       4 个网址   有新版   [更新] [停用] [删除]
▸ github.com       4 个网址   已是最新        [停用] [删除]
▸ tailscale.com    4 个网址   有新版   [更新] [停用] [删除]
```

- 未检查时不显示更新按钮；检查只拉取必要索引，不替换词库。
- 当前目标语言、网址清单或仓库配置变化后重新计算状态，不沿用过期检查结果。
- “全部更新”处理有新版的已安装分组，显示进度与成功失败数量；一个组失败不影响其他组。
- 更新中防止重复启动；成功后移除更新按钮；失败显示重试；冲突显示“处理冲突”。
- 停用网站更新后仍停用。更新或上传不能改变个人网站启用状态。
- 检查采用索引和缓存，限制并发与请求频率，处理 GitHub 限流和服务不可用。

“文件夹同步”页替换为“词库上传”：仓库和分支信息、固定目录、授权与连接状态、分组差异数量、内容预览、选择上传、最近结果及提交标识。

上传只允许写入 `dictionaries/` 内的支持文件，禁止路径穿越及源码、工作流、其他文件写入。浏览器凭据只保存在本设备受限制的上下文，内容脚本不可读取；不得内置共享写入令牌。最终认证方式在实现时结合个人使用和后续分发选择，不把当前聊天的 GitHub 连接当作插件运行时凭据。

仓库公开性沿用实际仓库配置，不擅自修改。公开仓库中的页面路径、上下文和稳定正文也可能包含个人或业务内容，上传必须展示范围并校验，不能将“通过采集保护”等同于“适合公开”。

完成标准：按钮位置及显隐符合要求，状态准确，上传预览可审阅，错误可恢复，界面明确区分 AI 生成、GitHub 更新与词库上传。

## 阶段六 回归验收与旧流程退出

| 范围 | 必测场景 |
| --- | --- |
| 旧词库转换 | 静态、正则、日期时间、属性、页面和子网站范围无退化 |
| 本机迁移 | 人工修改、选区标记、跳过项、各语言、冲突、删除状态保留 |
| 合并 | 同条不同改、不同条修改、相同结果、删除修改冲突、无基线数据 |
| 更新 | 下载中断、哈希失败、格式不兼容、分组原子切换、单组失败 |
| 上传 | 远端并发、上传期间继续编辑、提交结果不明、无变化不制造提交 |
| 网站管理 | 主域名更新、全部更新、停用保持、删除不影响公共词库 |
| 恢复 | 首次同步延迟、空值保护、缺失包下载、权限缺失、无 AI 调用 |
| 双设备 | 真实 Edge 账号同步、离线重连、清单删除不复活、两端修改 |
| 保护 | 凭据和任务不上传、源文追踪不退化、远端数据不执行代码 |
| 容量与中断 | 大 GitHub 词库、缓存空间、后台重启、同步配额和限流 |

根据改动运行 `npm run build`、`npm test` 及必要浏览器烟测；当前阶段不执行 `npm run package`。独立测试配置，不复用个人浏览器，不访问真实令牌。已通过检查没有新变化或失败理由时不重复运行。

真实双设备验收由实际设备和账号完成；不把自动化协议测试写成已完成云端或双设备验证。未能执行的验收明确记录。

迁移可用后移除旧自动 OneDrive 交换入口和重试调度，保留订阅所需 Native Messaging 能力。旧目录、备份和用户数据不自动清理。更新 README、实现验收文档、使用说明、相关 AGENTS 约定和版本变更记录，使文档与最终行为一致。
