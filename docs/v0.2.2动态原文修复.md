# v0.2.2 内置网站动态原文漏采修复

日期：2026-10-30。反馈级别 P2。修复仅在 `website-translator`，不更改原 `fixed-site-translator`，不安装本地主机，不操作真实账号或 OneDrive。

## 根因与范围

v0.2.1 的 managed 采集器在内置站点、目标 zh-Hans 时，把满足 oldValue 条件的 characterData 变化记为 `observed`，随后将其当成已被内置引擎翻译的节点跳过。MutationObserver 没有提供写入者身份，因此网站自己更新的英文也会走这条路径。采集器保留旧 source，既漏掉新英文，也可能影响后续原文恢复。

独立审查证据中，Tailscale 模拟页的 Pricing 被内置词库正确译成“价格”，但通知节点由 `Unlisted initial notice for independent review` 改为 `New untranslated notice after the site updates` 后，采集结果错误变成空数组。实际页面仍显示新英文，未发起 AI。

## 修复方式

1. 新增 `extension/text-provenance.js`，仅在扩展内容脚本的隔离环境共享。用 WeakMap 按文本节点保存 source、output 和 owner，不在网页属性中写入原文，也不接收网页脚本或 AI 给出的“来源声明”。
2. 内置引擎真正调用 DOM 写入时登记该次原文与输出。先处理此前待交付的外部变更，写入后同步提取并消费自己的确切 mutation，避免把网站变更归到插件名下。
3. 网站再次改写节点时，使旧登记失效。采集在观察器回调之前发生也会先处理待交付记录，连续多次更新取当前最新源文；不靠中文字符、文本相等或任意 DOM 变化推断来源。
4. `managed-content.js` 仅跳过明确登记为 builtin 的当前译文。增量翻译使用同一来源层，停止或切换时恢复最近的源文。普通网站使用相同路径。
5. `site-runtime.js` 以及 GitHub 通用文本、导航和选择器替换接入该层。内置规则未命中时不会撤销增量词库已有的译文；内置人工词库真实命中时仍优先。
6. 三端静态注入、动态注册及点击更新时的即时注入都在采集器之前加载新模块；未修改上游词库或同步基线。

源文进入候选不等于一定翻译。受保护内容仍在采集前排除，AI 仍只能翻译 ui/stable_content；浏览器测试的模拟服务返回 ui 仅用于验证采集与保存链路，不证明真实动态正文应被翻译。

## 回归与结果

`tests/text-provenance.test.cjs` 新增 5 个组合场景：

- 内置与普通网站字符节点更新、同一事件循环连续变化、整个文本节点替换。
- Pricing → Settings → 未收录英文 → Pricing：真正内置译文排除，未知英文重新采集。
- 内置和增量引擎共存，连续改写后停用及 zh-Hans/ja 切换恢复最新原文；DOM 层直接验证同一节点恢复，浏览器层另外验证实际刷新生命周期。
- 同一轮网站写入与内置写入交接，以及文本变化后又回到相同值，不保留旧来源推断。
- GitHub 通用文本及整元素选择器替换登记，重复扫描保留原文，后续网站改写可再次采集。

`script/test-managed-browser.cjs` 在独立 Chromium 中复现审查页面，实际加载生成的扩展：

- 原始通知、更新后的通知及连续改写后的通知均能采到；Pricing 的内置译文不进入候选。
- 两次新增模拟 API 请求分别只包含 `Latest untranslated notice after consecutive updates` 与 `Final source after another website update`，没有旧通知或“价格”。
- 重复点击更新已存项不增加请求；停用恢复原文与浏览器翻译标记，日文和中文切换不串译。
- 全部 14 个浏览器检查通过；总计 4 次模拟 API 请求，另外 2 次属于原有普通网站中/日文烟测。

完整验证：构建通过，`npm test` 的 121 项用例及独立脚本检查通过，`npm run test:browser` 通过，v0.2.2 打包和包内资源核对通过。无需真实 Key、订阅账号或 OneDrive。
