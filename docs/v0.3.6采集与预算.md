# v0.3.6 采集过滤、可调预算和强制重译

设置 → 常规新增以下选项，全部为整数，本机保存：

| 设置 | 默认 | 可填范围 |
| --- | ---: | ---: |
| 单页待处理条数 | 500 | 1–5,000 |
| 单页待处理字符数 | 80,000 | 1–400,000 |
| 多页会话待处理条数 | 3,000 | 1–10,000 |
| 多页会话待处理字符数 | 400,000 | 1–2,000,000 |
| 单次输入上下文，K tokens | 200 | 1–1,000 |

单页和会话均在条数、字符数任一个达到上限时停止新增。普通采集先按网站、原文、上下文、目标语言过滤已存词条（包括 skip）及可复用译文，再计入额度。原文来自 WTText，不以当前显示语言判断。连续更新会越过已处理内容，网页修改后的新原文仍能进入候选，其他语言的词条不会阻止当前语言采集。

保存采集设置后用于后续扫描及会话新增内容，不删除既有草稿。多页公共 UI 在会话计额前合并，保留实际出现过的路径；提交时展开路径后统一分批，一个结果写回多个路径。正文继续按路径隔离。额外路径引用最多 20,000 个，达到时显示截断。采集中切换目标语言需先完成或取消采集，避免因旧语言的过滤状态漏掉新语言内容。

输入预算包含提示词、术语、原文和格式开销，1K 为 1,000 个估算 token，不预扣预计输出。它是允许的输入上限，不能突破服务模型和传输字节限制；设置过低、连提示词及单项都放不下时，会明确报错并保留待处理内容。API 和订阅采用同一配置，native 再次校验。任务固定启动值，手动重试读取最新值。机器翻译仍遵守原服务的条数和字符限制。

## 右键强制重译

选择页面文字后右键“加入待翻译”，即使有 AI、人工或内置译文，也会在下一次点击更新时重新请求翻译。加入本身不调用 AI；相同待办去重。采集过滤不作用于手动队列，历史 skip 也不阻止请求。成功译文按操作的因果顺序覆盖旧结果，失败或服务仍跳过时保留旧译文与待办，不清空已有成果。

选择已有译文时使用来源层的原文，不能把中文译文作为外语原文发送。明确选择的新结果与人工修改共同参与优先级合并，之后的普通 AI 更新不能覆盖它。WTText 记录 `managed-selected` 写入，阻止内置引擎随后的文本或整元素写入改回旧译文；网站自身改写仍使来源记录失效。停用或语言切换正常恢复原文。

输入、代码、明确敏感区和邮箱保护继续生效。邮箱前标签仍只发送标签文字。右键队列仍使用独立的原有容量保护，不随普通采集额度变化。

## 实现与验证边界

共享协议 `managed-core.js` 校验采集设置；内容脚本在额度判断前过滤，后台采集再校验、过滤并合并路径。`managed-batching.js`、后台和 `native/oauth.cjs` 传递并校验可调输入预算。管理页展示设置与任务实际使用的预算。

测试使用合成词条、独立 Edge 配置和模拟翻译服务，不读取个人浏览器账号或真实令牌。浏览器菜单通过真实选区事件和已注册回调验证；真实模型上限及服务性能需实际服务验证。仅更新 `edge/` 及随附本地程序，不打包、不安装注册表，不修改原项目。
