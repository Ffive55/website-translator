# 网站翻译插件：现有词库使用说明

基于 [MaydayV/github-chinese](https://github.com/MaydayV/github-chinese) 的 `chrome` 分支 v3.1.2，保留原 GitHub 功能，增加按网站拆分的配置与通用词库引擎。当前项目总览见根目录 README.md，上游来源与许可见 THIRD_PARTY_NOTICES.md。

## 当前覆盖

| 网站 | 范围 | 实现 |
| --- | --- | --- |
| GitHub 及原有附属站点 | 原界面翻译、可选正文翻译等 | 原专用引擎 |
| Tailscale 官网 | 导航、链接、按钮和首页主要功能入口 | 本地词库 |
| Tailscale 工作台 | `console.tailscale.com/admin` 及旧 `login.tailscale.com/admin`，设备、用户、DNS、访问控制、日志、设置等常见入口与操作文案 | 本地词库 |
| Tailscale 登录页 | 登录入口、登录按钮、邮箱占位提示 | 本地词库 |
| Docker 官网 | `docker.com` 和 `www.docker.com`，首页主要功能区、导航、产品入口与价格页面常见文案 | 本地词库 |
| Docker 工作台和 Hub | `app.docker.com` 和 `hub.docker.com`，账户、账单、仓库、镜像搜索与详情、用量等常见界面 | 本地词库 |

首版重点是工作台和首页功能入口，不提供整站文章、文档长段落或任意未知文本的自动翻译。未收录文字保留原文。Tailscale 不需要 API Key，不发送页面内容到翻译服务；在线内容翻译设置仍只用于原 GitHub 功能。

Docker 同样使用本地词库。Docker Hub 用户撰写的镜像说明正文、镜像名称、标签和命令保留原文；可见页面检查范围和身份验证限制见 [Docker 页面检查记录](Docker页面检查记录.md)。

## 直接加载

仓库已包含生成好的三端扩展，可直接加载，无须先安装 Node.js。

1. Edge 打开 `edge://extensions/`，Chrome 打开 `chrome://extensions/`。
2. 开启“开发人员模式”，选择“加载解压缩的扩展”。
3. Edge 选择仓库中的 `edge` 文件夹；Chrome 选择 `chrome` 文件夹。
4. 刷新目标网站。扩展弹窗和翻译设置会显示各已注册网站。
5. 若同时安装了上游 GitHub 中文扩展，使用本版本时建议停用旧版，避免两个脚本重复修改 GitHub 页面。

Firefox 在 `about:debugging#/runtime/this-firefox` 中选择“临时载入附加组件”，打开 `firefox/manifest.json`。临时载入会在浏览器重启后失效；本地压缩包不是商店签名版本。

**仅已启用的网站阻止浏览器再次翻译。** 扩展在 `document_start` 读取总开关和对应网站开关，仅在两者均开启时写入 Chromium 支持的 `meta name="google" content="notranslate"`。禁用网站冷加载时不插入标记，GitHub 也不会把页面语言改成中文。此机制不修改浏览器全局语言设置，不删除站点自己已有的标记。

弹窗按钮名称为“翻译设置”。打开后，顶部“网站启用”列出 GitHub、Tailscale、Docker 官网、Docker 工作台与 Hub 等已注册网站，修改会自动保存。Docker 官网与工作台是两个独立开关。每个网站使用独立存储项 `site_enabled_<id>`，以后新增的网站也会自动出现在列表中。

切换网站开关时，该网站已打开的页面自动刷新，从原始页面重新加载，以清除旧译文、恢复原页面语言及浏览器语言检测。其他网站的选择保持不变。禁用后浏览器自带翻译恢复可用，是否自动翻译沿用浏览器原有语言设置；插件不会强制开启浏览器自动翻译。

总开关关闭时，所有站点均停止插件翻译，但各网站的独立选择仍保留；重新开启总开关不会把手动禁用的网站重新打开。下方的 GitHub 内容翻译设置继续独立保存，网站禁用时不会执行这些功能。

## 以后增加网站

开发测试使用 Node.js 24.15+（本次在 24.21.0 验证），先运行 `npm ci` 安装测试依赖。在仓库根目录运行：

```powershell
npm run site:add -- example https://example.com "示例网站"
```

这会新建 `sites/example/site.json`，不会覆盖已有配置。补充域名和词条，例如：

```json
{
  "id": "example",
  "name": "示例网站",
  "engine": "dictionary",
  "matches": ["https://example.com/*", "https://console.example.com/*"],
  "dictionary": {"Dashboard": "工作台", "Settings": "设置", "Save changes": "保存更改"},
  "selectors": ["nav", "header", "a", "button"],
  "ignore": [".user-generated-content"],
  "regexp": [],
  "pages": [
    {
      "pathPrefix": "/admin",
      "selectors": [],
      "dictionary": {"Members": "成员"},
      "regexp": [{"pattern": "^(\\d+) members$", "replacement": "$1 位成员"}]
    }
  ]
}
```

然后执行：

```powershell
npm run build
npm test
```

最后在扩展管理页点击“重新加载/刷新”，再刷新目标网页。新增域名可能需要浏览器重新确认站点访问权限。

构建器自动发现 `sites/*/site.json`，生成三端域名权限、脚本注入列表、弹窗网站列表和站点脚本。通常不需要修改核心代码，也不需要分别维护三份词库。新网站仍需实际页面验证，生成模板不代表完成汉化。

## 配置规则

- `id`：与目录名一致，只能使用小写字母、数字和连字符，必须以字母开头。
- `engine`：新增网站使用 `dictionary`；`github` 仅保留给 GitHub。
- `matches`：支持明确的 HTTP(S) 域名或 `*.example.com` 子域名形式，路径为 `/*`。不接受全站通配。不同适配器的域名不能重叠；页面差异放在同一适配器的 `pages` 中。
- `enabled: false`：构建时不注册此网站、不授予该网站权限。GitHub 适配器需保留。
- `dictionary`：完整文本匹配，大小写敏感，匹配前合并连续空白。避免可能误伤用户名、设备名的过于宽泛词条。
- `caseInsensitive: true`：可选，不区分英文大小写（Tailscale 已启用），解决表格全大写标题等变体。弯引号与省略号会统一匹配形式。
- `selectors`：限定翻译区域，空数组或不填写表示整个页面。页面规则可覆盖公共区域范围。
- `ignore`：追加不翻译区域，适合用户名、设备名或业务数据。内置代码、输入值、编辑区域和 `translate="no"` 等保护始终有效。
- `ignoreText`：只保护区域内的文本，仍允许翻译 `aria-label` 等提示属性。Tailscale 设备链接使用此规则，保留设备名称，同时翻译“查看设备详情”。
- `attributes`：默认翻译 `title`、`placeholder`、`aria-label`，可选 `alt`。不允许改写 `value`、`href`、`src` 等行为属性。
- `regexp`：包含 `pattern`、可选 `flags` 和 `replacement`。标志仅允许 `i` / `u`；要求匹配整个文本节点，可用捕获组翻译动态数字。
- `pages`：按 `location.pathname` 的 `pathPrefix` 匹配。按配置顺序合并，后面的页面词条覆盖前面的词条，免翻区域累加。更具体规则放后面。
- 页面规则可设 `exact: true`，仅匹配完全相同的路径。Tailscale 首页 `/` 使用此设置，扩大首页说明覆盖范围而不影响文档文章。

引擎只替换文字节点和允许的属性，不替换 `innerHTML`。动态内容通过 MutationObserver 处理。历史事件及每 500ms 的 URL 检查处理 SPA 导航，无须改写站点代码。当前通用引擎不进入 iframe 或 Shadow DOM，这类网站需要额外适配。

## 维护位置

```text
sites/github/site.json     原 GitHub 域名与引擎注册
sites/tailscale/site.json  Tailscale 词库、域名、页面规则
sites/docker/site.json    Docker 官网词库、域名、页面规则
sites/docker-hub/site.json Docker 工作台与 Hub 词库、域名、页面规则
extension/site-runtime.js 通用页面汉化引擎
script/add-site.js        新建网站配置
script/site-config.js     配置及域名冲突校验
script/build-sites.js     多网站构建
tests/sites.test.cjs      DOM 行为与构建测试
chrome/sites/            生成产物，请勿直接编辑
edge/sites/              生成产物，请勿直接编辑
firefox/sites/           生成产物，请勿直接编辑
```

修改 Tailscale 词条只需编辑 `sites/tailscale/site.json`，再构建与重新加载。原 GitHub 代码继续在 `chrome/src`、`chrome/locals.js` 维护，本次不重写上游引擎，便于后续同步。
