# v0.2.1 设计符合性审查

日期：2026-10-30。审查范围：`docs/新项目设计.md`、浏览器后台与管理界面、Native Messaging、本地 OAuth 与文件同步。结论：修复下列可复现问题后，可以继续进行真实账号与双设备验收；不将开发预览称为全部设计已验收。

## 已修复问题

| 编号 | 原问题与影响 | 修复与证据 |
| --- | --- | --- |
| AUTH-01 | 登录端口无 runtime.lastError 断开时 Promise 不结束；管理页关闭后本地回调仍等待 | 任意未完成断开都失败收束；管理页 pagehide 断开端口；主机 stdin 结束通过 AbortSignal 取消登录。UI 和真实子进程测试 |
| AUTH-02 | 回调缺少一次性消费和重复参数检查；取消与持久化之间存在竞争 | 限定 method/Host/path/state，拒绝重复参数和重放；finally 关闭 listener；写入中取消回滚旧账号。真实 loopback + jose 测试 |
| AUTH-03 | 新动态注册的 code 交换失败会丢失 issued client，下次重复注册；续期 invalid_grant 留下失效凭据 | 待验证注册与活动身份分离保存；失败后复用 issued client；无效续期清除令牌并保留身份，网络失败保留可重试会话 |
| AUTH-04 | 退出清除了文件但其他本地主机进程可能继续请求并接受迟到结果 | 仅本机的非秘密会话代次标记；退出先使会话失效，在途请求检测并取消，返回前再检查；远端撤销重试失败明确报告 |
| AUTH-05 | completed 事件缺少真实完成状态仍被接受；令牌类型与失效字段校验不足 | 必须 response.status=completed，拒绝重复终结、完成后增量与截断尾部；Bearer、scope、expiry 和 rotating refresh token 校验 |
| SYNC-01 | 总量按 JS 字符数判断；单条文件 30 KB 限制会拒绝自身产生的合法中文词条 | 总量按 UTF-8 实际字节预检；单条允许协议上界对应字节量；中文大词条与超限测试 |
| SYNC-02 | 缺 deviceId/schema 的校验封套也可能作为对端确认；新修改后旧确认不立即失效 | 严格确认字段/UUID/opId/重复检查；本机保存立即使确认失效；存在依赖或坏文件不显示全面确认 |
| SYNC-03 | 同步中修改遇 busy 后丢失后续交换机会；关闭同步后迟到结果仍可导入 | 合并并发触发并排队下一轮；配置修订号在导入、确认和发布状态前验证 |
| SYNC-04 | ack 写失败会跳过 registrations/broadcast，页面可能继续使用已删除词库 | 导入持久化后先注册及通知页面，再尝试确认；确认失败只影响同步状态 |
| SYNC-05 | 缺网站创建因果关系的记录被计为 applied；无前代删除依赖可构造高代次创建 | 非 create 必须因果依赖同代 create；重新添加必须因果依赖前代 delete；未知依赖继续等待而不确认 |
| SYNC-06 | 依赖于同步元数据 builtinId 识别旧 GitHub 凭据读取权限 | 只按随扩展分发的真实 GitHub origin 白名单授权，不让同步文件扩大权限 |

其他整理：保存临时文件失败时清理临时文件；确认/快照拒绝额外字段；同步 opId 内容冲突不降级为可忽略坏文件；导入本设备历史记录后递增序号不会倒退；管理页同步状态随实际结果刷新。

## 设计符合与边界

- 本机数据库仍在浏览器本机存储；同步只传纯数据白名单，OAuth/Key/设备私有设置和任务不导出。外来内容不执行脚本。
- 不可变日志、校验快照、依赖等待、删除代次、人工优先及并发候选保留。时间不参与覆盖选择。
- ChatGPT 使用独立官方授权，不访问其他应用登录文件；PKCE、OIDC 验签和本机 DPAPI 保留。授权、续期与模型请求都只按用户操作进行。
- 本轮没有操作真实注册表、账号、OneDrive 或原项目。测试产物只写入当前项目 `.cache/`。
- 未完成全量设计：全局/设备级语言覆盖、单账号之外的账号管理、同步分页与历史治理、上传前加密及配对仍没有实现；通用采集的 iframe/Shadow DOM/属性范围仍受预览限制。
- 强制终止进程或断电留下的会话锁仍采取保守人工恢复，避免误删正在轮换令牌的锁；正常取消/关闭已自动释放。

## 验证

新增及扩展测试位于 `tests/oauth.test.cjs`、`tests/native-host.test.cjs`、`tests/managed-ui.test.cjs`、`tests/managed.test.cjs`。OAuth 测试使用本机生成的签名密钥和合成响应，真实本地 HTTP 回调；Native 测试实际启动 Node 子进程，但只生成授权地址、不打开浏览器授权、不发真实账号请求。OneDrive 测试用项目内隔离目录。

最终构建、测试和打包结果见 `docs/实现与验收.md`；需用户执行的分步验收和预期结果见 [订阅与同步实测清单](订阅与同步实测清单.md)。
