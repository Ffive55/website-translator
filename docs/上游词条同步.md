# 上游词条同步

## 来源

当前固定从 [MaydayV/github-chinese](https://github.com/MaydayV/github-chinese) 的 `chrome` 分支读取 `chrome/locals.js`。该文件包含 GitHub 页面匹配规则、免翻区域、静态词条、正则及选择器翻译。

GitHub 词库的更上游是 maboloshi/github-chinese，但本项目的初始引擎来自 MaydayV 扩展分支，因此默认跟随这个兼容分支。不要仅修改 URL 就切换到另一种词库结构；变更来源需重新核对规则与引擎兼容性。

Tailscale 使用独立词库，不属于本同步来源。新网站也不会自动从 GitHub 上游获得翻译。

## 日常使用

```powershell
npm run upstream:check
```

该命令读取公开仓库最新提交，在 `.cache/upstream/<检查目录>/` 生成：

- `report.json`：来源、提交、内容指纹及状态。
- `upstream.patch`：上次同步的上游基线 → 最新上游的变化。
- `merged.patch`：本地词库 → 合并候选结果的变化。
- `merged.locals.js`：合并候选结果；有冲突时包含冲突标记。
- 本次的 current/base/incoming 三份输入，便于核对。

检查命令不会写入项目词库或更新基线。返回码 0 表示无变化或可合并，2 表示冲突，1 表示网络/配置/校验错误。网络失败不会被当成“没有更新”。

审阅差异后执行：

```powershell
npm run upstream:update
```

也可固定为检查报告中的提交，避免检查后上游又发生变化：

```powershell
npm run upstream:update -- --ref <report.json 中的完整 incomingCommit>
```

无需 GitHub 登录即可访问公开仓库。公开 API 受限时，会自动使用 `git ls-remote` 查询同一分支的精确提交，再下载该提交的词库。如果两条查询路径都失败，会报错退出，不把失败当作没有更新。也可在当前命令环境提供 `GITHUB_TOKEN` 改善 API 额度；不写入配置文件，不要提交令牌。

## 如何保留本地修改

同步使用 `git merge-file` 做三方合并：

1. `upstream/github-chinese/locals.base.js`：上次同步时的纯上游文件。
2. `chrome/locals.js`：当前本地文件，可能含本地修订。
3. 本次锁定提交中的上游文件。

不同位置的修改会合并；同一位置有不同改法时停止并保留冲突。同步前还检查三个浏览器词库一致、基线 SHA256 正确，避免覆盖遗漏在其他目录中的本地改动。

成功后只更新三个 `locals.js`、纯上游基线和 `lock.json`，然后执行 `npm test`。不替换 content.js 源码、Tailscale 词库、站点偏好、图标、manifest 或翻译接口设置。此流程保留 JS 注释、正则与文件排版，不把词库执行后再序列化。

## 冲突处理

发生冲突时，项目文件保持不变。编辑本次报告旁边的 `merged.locals.js`，解决 `<<<<<<< LOCAL`、`=======`、`>>>>>>> UPSTREAM` 标记，并保留需要的本地译法。

```powershell
npm run upstream:resolve -- .cache/upstream/<检查目录>/report.json
```

该命令会重新验证同一个上游提交，确认本地文件没有在检查后变化，再应用解决后的词库并运行测试。若报告已过期，重新执行检查。不要手工把基线换成本地修改后的文件，否则下次无法正确三方合并。

## 失败、回滚与发布

- 网络失败、格式变化、冲突、过期计划不会改动项目文件。
- 应用后的完整测试失败，会恢复三个词库、基线和锁定记录的原始字节。
- 报告目录中的 `validation.log` 保留检查输出，`backup/` 保留本次更新前的文件。
- 文件被其他程序锁定导致恢复失败时，工具会明确列出未恢复文件；按报告备份处理后再继续。
- 并发同步通过 `.cache/upstream/.sync.lock` 防止相互覆盖；异常退出后，先确认没有同步进程再删除遗留锁。
- 缓存与报告不应提交，提交的是成功更新后的词库、基线和锁定记录。

成功后运行 `npm run package`，审阅 Git 差异并提交。安装本地版本的用户需要重新加载扩展和目标网页。

同步不会自动推送 GitHub，也不会在浏览器启动时联网更新词库；只有维护者执行命令时才获取更新。
