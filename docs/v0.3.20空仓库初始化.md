# v0.3.20 空仓库初始化

## 使用

在“词库仓库”选择 GitHub 或 Gitee，输入连接令牌后点击“仓库测试”。检测只读，不修改任何候选仓库。

- 已有有效词库：显示“已有词库”，点击“确认仓库”直接连接。
- 真正空仓库：没有分支或标签，显示“空仓库”，点击“初始化并连接”自动上传初始内容，验证后连接。初始化需要写入权限；平台明确报告只读或归档的空仓库不作为初始化候选。平台未明确报告权限时会注明待验证，实际提交权限由服务端判断。
- 本设备初始化中断：显示“初始化未完成”，点击“继续初始化并连接”，先核查已上传内容，再新增缺少的文件。

已勾选生成 README、许可证或 .gitignore 的新仓库已有提交，不属于空仓库；没有有效词库索引时不会列为初始化候选。无权限、请求失败、无效索引不能作为空仓库的依据。

初始数据只包含 **https://github.com 主站、zh-Hans**，不含 Gist、Education、Skills、GitHub Status 或其他网站。后续新增网站仍通过正常词库更新上传。README 只介绍仓库和插件连接方式，不维护网站清单。

连接完成后，在网站管理中搜索并下载 GitHub 词库。仓库连接、平台令牌和 AI 设置继续按 v0.3.19 的浏览器设置同步方式保存。

## 实现

`script/build-repository-seed.cjs` 从静态转换后的 GitHub 主站 JSON 生成单分组索引与清单，随 Edge 压缩分发到 `managed/repository-seed.json.gz`。该文件只在用户确认初始化时解压，不接入网页翻译回退、旧 locals.js 或 AI。

初始化固定新增八个文件：事务标识、README、LICENSE、THIRD_PARTY_NOTICES、source.json、GitHub 主站 JSON、分组 manifest 和总 index。保留 GPL-3.0-or-later、上游归属和固定来源提交。上传数据不含用户本机词条、API Key 或连接令牌。

`dictionary-initialize.js` 使用 GitHub Contents PUT（不传 sha）或 Gitee Contents POST，均只创建新文件。每步检查仓库身份、权限、分支、标签及固定提交的递归文件树，与预期 Git blob 标识比较；发现其他内容、已改文件、其他分支或标签则停止，不覆盖、删除或强推。仓库测试到确认期间也重新检查空状态。

每个文件提交前将事务写入本机 `wt_dictionary_initializations`，不记录令牌、不进入浏览器同步。后台每条确认请求最多创建一个文件，设置页自动继续并显示进度。关闭页面可停止后续请求，已经发出的请求可能完成；重新打开页面、测试仓库后继续核查。服务器响应丢失后保留事务，重试先读文件树；已成功的文件直接跳过，同路径创建竞争由平台拒绝。

总索引最后创建，因此部分上传不会被其他设备当成有效词库。最后重新下载并完成协议及 SHA-256 校验，才保存新连接并同步。初始化是多个提交，不声称原子发布；外部并发写入可能使初始化停在部分完成状态，已有文件保留。正常已有词库的上传路径不受影响。

若初始化途中更新插件且内置种子发生变化，会拒绝混用版本；应使用原插件版本完成该事务。中断事务只在发起设备保留，其他设备不会自动接管不完整仓库。

## 接口依据与验收边界

- GitHub 官方明确说明空 Git 数据库可能返回 409，须先用 Contents 创建文件再使用 Git 数据库接口：[官方说明](https://docs.github.com/en/rest/guides/using-the-rest-api-to-interact-with-your-git-database)、[Contents API](https://docs.github.com/en/rest/repos/contents)。因此不使用“先创建 Git tree/commit”的方式初始化空仓库。
- Gitee 官方 [API 文档](https://gitee.com/api/v5/swagger) 及其 `https://gitee.com/api/v5/doc_json` 定义提供新建文件 POST、Base64 内容、自动使用或指定分支，以及分支、标签和递归 Tree 的查询。本实现按这些接口逐文件新增。
- 开发验证采用真实生成的 GitHub 主站初始化包、模拟两平台 API，以及隔离 Edge 后台/设置页。覆盖空状态判定、只读权限、已有仓库保护、响应丢失、恢复、索引最后发布、仅主站内容及确认前不写入。
- 未对真实 GitHub/Gitee 空仓库执行写入验收，真实账号权限、平台限流及大文件上传接受情况仍需实际使用验证。不会把模拟服务测试表述为真实远端上传通过。

2026-10-31 本地验证：`npm run build` 完成 Edge 解压目录构建，`npm test` 185 项通过；隔离 Edge 运行时 47 项检查通过，包括真实压缩种子读取、首文件响应丢失后重新打开设置恢复、八个文件无重复创建、仅 GitHub 主站目录以及原有设置同步回归。最后的停止提示文案调整后，管理页 15 项测试复验通过。无真实远端写入、打包、安装或插件源码推送。
