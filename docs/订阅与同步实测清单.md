# v0.2.2 订阅与同步实测清单

日期：2026-10-30。以下步骤需要用户在真实浏览器、ChatGPT 账号及两台电脑上完成。本次开发只使用项目 `.cache/` 下的测试目录、合成凭据和模拟服务，没有安装注册表项、打开真实授权页或写入真实 OneDrive。

## 准备

1. 在电脑 A 加载 v0.2.2 对应的 Chrome/Edge/Firefox 扩展目录并重新加载。不要加载原 fixed-site-translator 目录。先选日常实际使用的一种浏览器；三浏览器的原生消息注册验收需要分别重复。
2. 本地连接程序需要 Node.js 24.15+、PowerShell 7 和完整源码。打开源码根目录，执行 `npm ci`。在浏览器扩展详情页复制本次扩展 ID。
3. 执行安装命令（由你运行；开发测试没有代为安装）：

```powershell
# 在项目根目录执行下列命令
pwsh -File .\native\install.ps1 -Browser edge -ExtensionId <32位扩展ID>
# Chrome 换成 -Browser chrome；Firefox 用 -Browser firefox，无需 ID 参数
```

4. 管理页点击“检查连接状态”。预期：连接成功且未登录。找不到主机时核对浏览器类型、扩展 ID、源码路径和 Node/PowerShell 是否可启动；不要以“注册脚本运行成功”代替此检查。
5. 选择一个不含账号资料、设备名称或业务内容的测试网页。需要至少生成一条增量词条，已被内置人工词库完全覆盖的页面可能不会请求 AI。

## A. ChatGPT 真实账号验收

| 步骤 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| A1 授权 | 点击 Continue with ChatGPT，保持管理页打开，在官方 auth.openai.com 页面完成授权 | 回到管理页后显示登录完成；检查连接状态显示预期账号。回调页“已收到”本身不代表登录成功 |
| A2 模型与首批请求 | 点击读取订阅模型，选择列表中的模型，保存为 ChatGPT 翻译来源；到测试网页点击添加/更新 | 任务完成并保存译文；账号无权限、计划不适用或用量不足时应明确失败，保留原词库。不要用“读到模型列表”代替实际推理验证 |
| A3 本地复用 | 记录词条数，刷新页面、关闭重开浏览器并访问同页，不点更新 | 已存词库仍可用，不产生新的翻译任务；检查登录记录仍可读取 |
| A4 续期 | 自然等待当前访问令牌到期后，再读取模型或更新一个新词条；不要手动查看或编辑令牌文件 | 无需复制其他应用登录文件即可成功续期；确需重新授权时清楚提示。仅重启浏览器不证明续期已验收 |
| A5 拒绝与取消 | 登录时拒绝授权；另一次开始后关闭管理页，再重开管理页 | 不显示假成功，不永久停在等待；旧已验证账号保持原状；再次登录不应被本次取消遗留的锁阻挡 |
| A6 退出 | 在管理页退出，再检查状态、读取模型 | 本机显示未登录，模型请求要求重新登录；若网络断开导致远端撤销未确认，应明确显示该事实。必要时到 ChatGPT 设置断开应用 |
| A7 并发与在途退出 | 一次更新进行中从另一管理页退出；也可同时从两窗口点击登录/读取模型 | 在途请求被取消或其结果丢弃；文件锁串行化授权和续期，不混用账号；忙碌时明确提示重试 |
| A8 浏览器注册 | 对实际要使用的其他浏览器重复安装和 A1/A2/A6 | 各浏览器都能启动本地主机，Firefox 的固定 ID 配置有效；不能以 Chromium 烟测替代 |

当前仅管理一个注册账号，同一 Windows 用户下的各浏览器共用本地主机的订阅会话；在其中一个浏览器退出也会影响其他浏览器。退出保留原账号/client 映射用于重登；多账号选择器尚未提供。正常关闭管理页或浏览器会取消等待中的登录。若直接强制杀进程或电脑断电后残留 `%LOCALAPPDATA%\WebsiteTranslator\session.lock`，程序会保守拒绝续期；确认所有相关本地主机进程退出后才可移除锁，再重试。不要在进程仍运行时删锁。

## B. OneDrive 双设备验收

建议使用独立测试浏览器配置和临时测试根目录，例如 `website-translator-test`，避免把已有私人词库混入测试。根目录只能用英文、数字、连字符或下划线。每台电脑先确认自己的 OneDrive 实际路径，再由你创建测试根目录；不能仅因路径含 OneDrive 就认定客户端已配置。

电脑 B 安装同版本扩展和本地主机，但不填写 API Key、不登录 ChatGPT；选择对应的同一 OneDrive 云端文件夹。两台电脑的本机绝对路径可以不同。

| 步骤 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| B1 缺失路径 | 先填一个不存在的测试路径并检查，然后改为已确认存在的目录 | 缺失路径明确失败，不创建替代目录，不显示已配置成功；改正后出现 changes/snapshots/backups/acks |
| B2 首次传输 | A 生成至少一条词条并“立即检查”；等待 OneDrive 客户端完成传输后，在 B 检查 | B 出现同一网站和词条。B 先显示待本机授权；授权并刷新同页后直接使用译文，无 AI 凭据也不发起翻译 |
| B3 对端确认 | B 合并后等待其确认文件传回 A，再在 A 检查 | A 才显示对端合并确认；只有 A 写出文件时不能显示该状态。确认后在 A 修改一项设置，应立即变回待交换/尚无对端确认 |
| B4 离线独立修改 | 暂停两台的 OneDrive 客户端传输，分别修改不同网站设置或不同词条；恢复客户端并让两台检查 | 两边改动都保留；没有因时钟快慢而整库覆盖 |
| B5 人工冲突 | 在两台都已收到同一词条的前提下，暂停传输，分别给同语言同词条保存不同人工译文；恢复并检查 | 管理页保留并发候选；保存一次明确选择后，两边再次同步应收敛；AI 不能覆盖人工译文 |
| B6 删除不复活 | B 暂停传输；A 删除网站并同步；B 对旧网站做修改再恢复传输并检查 | 旧代次词条不让网站复活。A/B 均保持删除；只有用户主动再次添加才创建新代次 |
| B7 语言隔离 | A 为同一网站分别生成或修正 zh-Hans 与 ja 词条，同步到 B 后分别切换 | B 两种语言互不覆盖；切换恢复原文并匹配对应词库；没有凭据也能复用 |
| B8 同步进行中变更 | 同步进行中保存新的词条/设置；另一次同步过程中关闭同步或改变路径 | 新修改会排入下一轮；关闭/改路径后旧结果不导入或显示成功。已经写出的文件不会被撤回 |
| B9 目录/网络故障 | 暂停客户端或临时使测试目录不可访问，然后修改本机词条 | 本机译文仍可用，状态显示待同步/失败；恢复后检查可以继续。写入本地目录和云端传输分别判断 |

协议层已自动覆盖文件乱序、重复副本、坏校验、opId 冲突和缺少依赖。若要进一步用 OneDrive 实测这些情形，只在上述可丢弃测试目录操作：先保存副本，再分批传入完整变更文件；不要改写真实词库中的不可变文件或清理删除标记。

## 回传什么信息

每项记录：步骤编号、通过/失败、浏览器名称和版本、两台扩展版本、界面显示的错误和任务数量。同步问题补充两台是否已显示 OneDrive 客户端传输完成、是否出现待依赖/非法文件/对端确认。

不要回传 API Key、chatgpt.dat、授权 URL 的完整查询、验证码、令牌或包含私人词条的整份目录。发生授权失败时，提供界面中的 HTTP 状态或错误分类即可。

## 尚未承诺的能力

- 真实账号是否获准使用订阅额度、哪些模型可用及实际用量，以 A1/A2 实测为准。
- 同步单次约 850 KB UTF-8 数据以及 10,000 条记录上限仍保留；没有分页或历史压缩，不自动清理删除标记。
- 同步文件没有端到端加密，校验和只验证完整性，不认证发送设备；只使用自己控制的目录。
- 全局目标语言和每设备仅本机的语言覆盖设置尚未接入，目前为网站级选择。单账号界面、通用采集范围等其他预览限制仍见实现与验收文档。
