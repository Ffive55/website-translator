# v0.3.21 词库定向覆盖

## 用户操作

“更新”与“上传”可以同时存在：前者表示仓库内容与已安装内容不同，后者表示本机存在待上传修改。内容标识只用于判断不同，不用时间戳推断译文优劣。

有完整共同基线时进行三方比较。不同词条的修改及相同结果自动合并；双方修改同一词条为不同结果、删除与修改相撞时先询问：更新采用仓库的冲突项，上传采用本地的冲突项。其他修改继续保留。

本机缺少完整基线，或仓库当前提交曾被本机较新内容替换时，提示无法可靠比较。确认更新将整份采用仓库，丢弃本地独有修改；确认上传将整份采用本地，仓库独有内容可能移除。范围是当前主域名分组、当前目标语言。词库文件的有效引用随该快照切换；仓库中不再引用的旧数据文件不主动删除，其他分组和语言保留。没有下载过静态适配器的本地快照只包含本地已知内容，整份上传也不会凭空补齐仓库适配器，因此确认文字明确说明替换完整词库。

取消不覆盖。设置页、扩展弹窗、全部更新及上传全部使用相同规则；批量按分组顺序检测和询问，取消一组后可以继续其他组。

## 实现

- `dictionary-core.js` 根据共同基线、修改层和仓库记录比较；`comparisonReason` 标明无法可靠比较的原因，`preferConflicts` 只解决冲突项。
- `dictionary-store.js` 的 preview 校验候选而不写入。确认后 install 在 IndexedDB 同一事务中校验本机修订、保存旧状态并切换；整份下载为被舍弃的本地独有词条保留删除标记，避免旧操作重新显示。
- `dictionary-publish.js` 准备局部合并或本地完整快照，保留其他分组和语言。完整快照包括本机已有的静态适配器，重算文件哈希、清单和索引；仍用普通提交发布，GitHub 不执行 force push，Gitee 保留文件版本检查。
- `dictionary-runtime.js` 保存十分钟、最多八份内存确认计划。计划固定仓库、凭据身份、网站安装上下文、语言、本地修订及仓库提交，UI 仅传确认 ID。后台重启、超时或状态变化后必须重新检测，不接受 UI 自行指定覆盖模式。
- 确认上传后仍在分支写入前复核本地与远端状态；已明确未写分支的失败标记为 rejected，请求结果不明则核查已有事务。网络、权限、格式及哈希校验失败不转换为覆盖确认。
- 覆盖前在本机 IndexedDB `meta` 的 `overwrite-backup:<组键>` 保存最近一份旧状态；这不是浏览器同步或可导出的备份界面。远端旧内容保留于普通提交历史。
- `managed-ui.js` 与 `dictionary-confirm.css` 为设置页及弹窗提供有取消按钮的模态确认，默认焦点在取消。批量入口先取得待处理列表，逐组检测、确认、执行。

## 验证边界

只构建 Edge 解压目录。测试使用独立 Edge 配置及模拟 GitHub/Gitee 网络；不读取个人浏览器数据，不访问真实令牌，不向真实仓库写入，不安装本地程序或修改注册表。

协议、UI、真实 IndexedDB 和后台集成测试覆盖自动合并、局部双向冲突确认、取消、确认期间新修改、整份覆盖、删除标记、旧状态备份、批量逐组处理与普通提交。自动化验证不等于真实账号及多设备人工验收。
