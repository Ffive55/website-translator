# v0.3.1 Edge 本地测试说明

2026-10-30。本轮只更新 Edge 解压目录，不生成 ZIP，不安装本地主机，不改注册表，不读取个人浏览器账号或真实令牌，不改原 fixed-site-translator。

## 测试入口

在 Edge 的扩展管理页重新加载 `edge/`，刷新设置页和目标网页。`npm run build` 只构建 Edge，并准备 `edge/local-helper/`；`npm test` 针对 Edge 产物和公共协议运行回归；浏览器烟测使用独立 `.cache` Edge 配置，不使用个人配置。

## 随插件附带的本地程序

`edge/local-helper/` 包含 Windows x64 Node.js 24.21.0、jose、Native Messaging 主机和安装脚本。首次构建从 Node.js 官方取得固定版本的归档并核对固定 SHA-256；之后使用校验过的缓存。许可和来源均随目录保留。该生成目录被 Git 忽略，不加入源码历史。

无需另装 Node.js、npm 或 PowerShell 7。安装及 DPAPI 使用 Windows 内置 PowerShell，凭据加密格式保持兼容。首次双击 `edge/local-helper/Install.cmd`，粘贴设置页显示的当前扩展 ID。浏览器不允许扩展自行注册本地主机，因此这一步需要由用户运行；修改文件夹位置或扩展 ID 后重新运行。

文件夹同步页直接提供本地连接设置、浏览器选择、扩展 ID、复制安装命令和连接检查。AI 翻译页的同一安装说明仍仅在 ChatGPT 订阅下显示。文件保存不要求订阅或登录；连接检查只发送 ping，不读取 OAuth 令牌。

`Access to the specified native messaging host is forbidden` 对应本地主机没有授权当前扩展 origin。请核对浏览器选择和当前扩展 ID 后重新运行安装命令，再检查连接。官方排查依据：[Native messaging 常见错误](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。

## OneDrive 自动保存

1. 在“文件夹同步”勾选自动保存，默认路径为 `%USERPROFILE%\OneDrive\文档\website-translator`；也可填写实际 OneDrive 内的目录。
2. 点击“确认目录并启用自动保存”。程序自动创建词库目录，进行短暂的写入、回读和删除探针，并返回解析后的实际路径。默认路径的 OneDrive 根目录必须已经存在；不存在时提示配置客户端，不创建一个假的 OneDrive 根目录。
3. 确认成功后，每个成功翻译批次、人工修正、网站启停或删除都会先持久化本机副本，再排队写入确认的目录。普通 API 使用者同样适用。
4. 正在写入时发生的新修改进入下一轮。导入的远端数据不反复触发自身导出。目录或启用状态变化会丢弃旧配置的迟到结果。
5. 写入失败保留浏览器词库，显示未保存及原因；浏览器闹钟安排约一分钟周期重试，设备休眠可能延后；后台或浏览器重启会恢复尝试。暂停自动保存即停止后续写入和重试。

浏览器本地运行数据为 `wt_database` / `wt_view`。目录内交换 `changes/`、`snapshots/`、`backups/`、`acks/`；不会同步 API Key、订阅令牌、提示词或采集草稿。目录存在、可写和词库文件已写入，不代表 OneDrive 客户端已上传，也不代表其他设备已接收。页面分别显示本机保存、目录写入和对端确认。

旧版本已经勾选同步但未经本版目录确认的设置，不会被认定为已完成确认；重新保存一次配置即可。

## 提示词、下拉列表和字号

提示词位于 AI 翻译服务下方的独立表单，所有服务下始终显示，独立保存到 `wt_prompt`。首次升级迁移当时启用服务的提示词；其他旧配置保持本机保留。切换服务不改动已保存或正在编辑的提示词。对话模型与 ChatGPT 共用；DeepL、Google、Azure、Qwen-MT 不使用通用提示词，界面明确说明。

目标语言使用标准 select，展示完整语言列表；ChatGPT 模型使用标准 select，读取模型后展示完整列表，并记住本机模型目录；不会用已选文字过滤。自定义 API 模型保留文本输入。

正文和按钮明确设置 14px，表单标签、输入框、下拉框及提示词为 16px，对齐原插件。显式覆盖扩展页面的浏览器默认 body 字号，保持单行按钮和双列网址布局。
