# v0.3.2 单页应用持续采集修复

日期：2026-10-30。仅更新 Edge 解压目录，不打包；没有操作个人浏览器、真实 OpenRouter 账号或调用真实翻译服务。

## 问题与根因

用户反馈：开始采集后一直显示 0 页 / 0 项，切换页面也不累计，只有完成时当前页能够翻译。

在独立 Microsoft Edge 中复现了相同行为：先在 `/initial` 注入内容脚本，再通过 `history.pushState` 切到 `/logs` 开始采集。浏览器传给后台的 `sender.url` 仍为 `/initial`，`sender.tab.url` 和采集文本路径已经是 `/logs`。旧后台把每条文本路径与旧 `sender.url` 比较，整批拒绝；内容脚本没有展示拒绝原因。完成按钮主动读取当前标签网址后补采，所以只有最后一页能处理。

## 修复

- 消息来源 origin、采集会话、授权标签和顶层 frame 仍然校验；页面路径改用隔离环境采集器记录的快照路径，不再使用文档初始路径。
- 采集快照明确携带 path；路径格式、条目路径一致性和排除路径仍验证。旧内容脚本没有快照 path 时，使用消息里标签的当前网址兼容。
- 开始采集时主动保存一次当前页，成功返回前已经持久化初始快照。
- 在途采集期间的新页面变化在请求完成后补发；只有后台确认实际保存才记为成功，失败有界重试。
- 后台校验失败写入会话的 lastError，弹窗显示原因；后续采集成功清除错误，不再静默显示 0 项。
- 保持同网站、同语言、同上下文公共界面去重；采集阶段不请求 AI，仍由完成按钮统一提交。

## 验证

专门的 Edge 复现脚本在修复前显示 0 页 / 0 项，修复后在相同 SPA 操作下显示 1 页 / 2 项。日志证明 sender.url 仍是初始地址，修复使用了新的采集快照路径。

自动化覆盖启动前 SPA 导航、采集中 pushState / replaceState、动态注册表单、完整页面跳转、同域 window.open 子页面、在途修改、来源域名与 frame 拒绝、排除路径、错误恢复。多页浏览器回归在点击完成前检查五个路径已经入库，之后核对较早页面文本也进入统一翻译批次，公共按钮只发送一次。

本轮结果：Edge 构建通过；86 项功能/协议回归和 13 项词库回归全部通过；Microsoft Edge 156.0.4314.50 独立浏览器回归通过。测试页面与翻译服务为隔离模拟，不作为真实 OpenRouter 账号验收。

更新后重新加载 Edge 扩展并刷新目标网页；旧的 0 项会话可取消后重新开始。此前没有采集到的页面需要重新打开，不会凭空恢复。
